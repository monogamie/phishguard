# Четвёртый заход — ревью на Fable, 15 ноября 2026

Два обзорных ревью вместо охоты по точкам: **логика баллов целиком** и
**безопасность**. Код не менялся. Каждую находку я перепроверил сам —
отметка «проверил» значит, что я запускал свою команду, а не скрипт
агента. Известные 33 находки третьей охоты (`FINDINGS.md`, G-01…G-33)
здесь не повторяются; где находка их обобщает — так и сказано.

Стенд для проверок, сохранить как `/tmp/off.py` и запускать из `backend/`
(зрелый домен, сертификат в порядке, базы чистые; подменяется то, что
передано в `kw`):

```python
import sys, logging; sys.path.insert(0, '.'); logging.disable(logging.CRITICAL)
from models import *
from pipeline.lexical_analyzer import lexical_analyzer
from pipeline.scorer import calculate_risk_score
def sc(url, orig=None, **kw):
    base = dict(gsb=ThreatIntelResult(checked=True), reputation=ReputationResult(checked=True),
        domain_age=DomainAgeResult(checked=True, age_days=4000),
        tls=TlsResult(checked=True, age_days=120, covers_domain=True),
        ct=CtResult(checked=True, first_seen_days=4000, total_certs=30))
    base.update(kw)
    r = calculate_risk_score(url=url, original_url=orig or url, lexical=lexical_analyzer.analyze(url), **base)
    return r.risk_score, r.verdict.value, round(r.confidence, 2), [(s.code, s.weight) for s in r.signals if s.weight]
if __name__ == "__main__":
    for u in sys.argv[1:]: print(f"{u:55}", sc(u))
```

### H-01. Схема обмана ищется в пути — честные магазины «подозрительные»

- **Что не так:** тревожные слова в пути обнулили ещё 20 сентября, а для
  `SCAM_PATTERN` поиск остался по `path + host`. `delivery`/`dostavka`
  из одной группы и `pay`/`oplata` из другой есть на странице «Доставка
  и оплата» у каждого магазина.
- **Воспроизвести:**

```bash
cd backend && python3 /tmp/off.py https://www.onlinetrade.ru/about/delivery_and_payment/ \
  https://www.lamoda.ru/help/delivery-and-payment/ https://www.vseinstrumenti.ru/dostavka-i-oplata/ \
  https://detsad-solnyshko.ru/konkurs-risunkov
```

- **Получили:** первые три — 35 SUSPICIOUS (`SCAM_PATTERN` 35); детсадовский
  конкурс рисунков — 57 (`SCAM_PATTERN` 35 + `TRIGGER_KEYWORDS` 22, одни и
  те же слова дважды).
- **Цепная реакция:** схема включает `address_is_a_lure`, и обычная форма
  входа на такой странице начинает весить. По агенту
  `dostavka-edy.ru/oplata` с паролем и входом через VK — 80 ОПАСНО.
- **Где:** `backend/pipeline/lexical_analyzer.py:425-427`, `scorer.py:437-442`.
- **Направление:** засчитывать схему, только если хотя бы одно слово
  связки стоит в имени домена — как уже сделано для ключевых слов.
- **Осторожно:** не сломать G-09 и `test_founding_scam_is_caught_in_its_real_forms` —
  там есть `x.top/golosuy-za-malysha` (схема целиком в пути на дешёвой зоне).

### H-02. Переадресация на доверенный сайт стирает исходный адрес

- **Что не так:** лексика считается только по конечному адресу
  (`main.py:233`). Если фишинговый адрес переадресует сканер на настоящий
  сайт, срабатывает потолок доверия, а исходный адрес не разбирается вообще.
- **Воспроизвести:** стенд выше, `sc("https://www.sberbank.ru/",
  orig="https://sberbank-vhod-online.top/login", redirects=RedirectInfo(resolved=True,
  final_url="https://www.sberbank.ru/", chain=[orig, final], hops=1, changed_domain=True))`.
- **Получили:** без переадресации этот адрес — 97 ОПАСНО; с переадресацией
  на `sberbank.ru` — **15 БЕЗОПАСНО, достоверность 1.00** (единственный след
  `CROSS_DOMAIN_REDIRECT` 20 срезан потолком).
- **Почему это не теория:** маскировка (cloaking) — штатный приём: сканеру по
  адресу дата-центра отдают настоящий сайт, жертве с телефона — подделку.
  На живом маскирующемся сайте не проверено, сборка ручная.
- **Где:** `backend/main.py:228-233`, `backend/pipeline/scorer.py:785-790`.
- **Направление:** при смене домена разбирать лексикой и исходный адрес;
  потолок доверия не применять, если исходный домен сам не доверенный —
  это условие у существующего правила.

### H-03. Достоверность считает «уровень ответил», а не «уровень узнал»

- **Что не так:** страница с кодом 403/503 (бот-защита отдала заглушку)
  имеет `checked=True` и идёт в числитель достоверности.
- **Воспроизвести:** `sc("https://new-shop-xyz.ru/", domain_age=DomainAgeResult(checked=False, error="x"),
  page=PageResult(checked=True, status_code=403, bytes_read=300), redirects=RedirectInfo(resolved=True, final_url=...))`.
- **Получили:** 5 БЕЗОПАСНО, **достоверность 0.88** — страницу не видели,
  возраст не знаем, а человек видит зелёную галочку. Порог «НЕ ПРОВЕРЕНО»
  на странице — `< 0.5` (`index.html:1783,1805`).
- **Где:** `backend/pipeline/scorer.py:105-138`.
- **Направление:** уровень идёт в числитель, только если принёс
  содержательный ответ (страница 2xx, возраст числом). Балл не трогается.
- **Заметка:** это прямо принцип №2 проекта — «не смогли проверить ≠ безопасно».

### H-05. Матрица «сильный признак × мелочь» (обобщение G-02)

Агент посчитал для каждого сильного признака, какая мелочь добивает его
до 60 (таблица целиком была в его скретчпаде, `matrix_pairs.md`):

| Сильный признак | Что добивает до красного |
|---|---|
| бренд / опечатка 55 | любой признак, включая `DOMAIN_AGE_UNKNOWN` 5 |
| гомоглиф 60 | красный сам по себе |
| `@` 50; домен моложе недели 50 | любая десятка: цифра, дешёвая зона, скрытые поля, `CT_NO_RECORDS` |
| `URLHAUS_HOST` 45; смешение алфавитов 45 | любая пятнадцать: http, длинный адрес, домен до 90 дней |
| IP 40; чужой сертификат 40 | `REDIRECT_PARAMS` 20 (см. H-06 — он срабатывает на `?to=LED`) |

Как часто мелочь бывает у честных сайтов (агент; первые 20 000 доменов
рейтинга Tranco + 64 настоящие страницы): цифры в домене — 7,4 %,
скрытые поля формы — 14 % страниц (hh.ru, megafon.ru, cian.ru, who.int),
дешёвая зона — 1,6 %. На Tranco 20 000 при ответившем реестре красных 8;
**при молчащем реестре — 144**: каждый домен с брендом в имени становится
ОПАСНО от одних +5.

- **Проверил сам:** арифметику пар — да (это прямо следует из весов в
  `config.py`, и G-02 уже подтверждал её на бою); частоты по Tranco — нет,
  это цифры агента.
- **Направление агента:** `DOMAIN_AGE_UNKNOWN`, `DIGITS_IN_DOMAIN`,
  `PAGE_HIDDEN_INPUTS` сделать пометками без веса — на вердикт они влияют
  только как «добивка». Вес 55 при этом можно не трогать. **Решать автору**
  вместе с вопросом о весе бренда.

### S-01. Один запрос замораживает весь сервер на ~10 секунд

- **Что не так:** кодировку страницы задаёт проверяемый сайт заголовком
  `Content-Type: text/html; charset=punycode`; httpx честно отдаёт
  `resp.encoding = "punycode"`, а `raw.decode(...)` выполняется синхронно
  в цикле событий. Кодек `punycode` на 256 КБ цифр работает ~11 секунд,
  и всё это время сервер не отвечает никому — даже `/health`. Общий
  дедлайн синхронный код прервать не может.
- **Воспроизвести:**

```bash
cd backend && python3 -c "
import time, httpx
print(httpx.Response(200, headers={'content-type':'text/html; charset=punycode'}, content=b'<p>').encoding)
raw = b'9' * (256*1024); t = time.time(); raw.decode('punycode', errors='replace'); print('%.1fs' % (time.time()-t))"
# punycode
# 11.4s
```

  Сквозь сервер (агент): `/health` во время такого скана отвечал **8.4 с**.
- **Где:** `backend/pipeline/page_analyzer.py:298` (`encoding = resp.encoding`),
  `:312` (`raw.decode(encoding, ...)`).
- **Масштаб:** воркер один (`Procfile: --workers 1`), лимит 30 запросов в
  минуту — по расчёту хватает, чтобы один адрес держал сервис лежащим.
  Агент перебрал все 120 кодеков стандартной библиотеки — медленный
  только `punycode`.
- **Направление:** не доверять кодировке сайта вслепую — список
  разрешённых кодировок для HTML (или хотя бы запрет `punycode`/`idna`).

### S-02. Сайт роняет проверку в 500 одним заголовком `Location: //[`

- **Что не так:** `urljoin` в разворачивании переадресаций стоит вне `try`
  и на битом IPv6-литерале бросает `ValueError`. Строчкой ниже `urlsplit`
  в `try` обёрнут — а до него дело не доходит.
- **Воспроизвести:**

```bash
python3 -c "
from urllib.parse import urljoin
urljoin('https://a.com/x', '//[')"
# ValueError: Invalid IPv6 URL
```

  Сквозь сервер (агент): `/scan` → 500 «Внутренняя ошибка сервера»,
  `/scan/stream` → `event:error 500`, `/batch` → элемент с `risk_score 0` (G-15).
- **Где:** `backend/url_resolver.py:138` (`next_url = urljoin(current, location.strip())`).
  В `page_analyzer.py` такой же вызов обёрнут в `try`.
- **Чем опасно:** сканер честно представляется `PhishGuardBot`, и
  фишинговый сайт может отвечать ему так — вердикта не будет никогда.

### S-03. Переадресация разбирается не так, как в браузере

- **Что не так:** обратный слеш на входе приводится к браузерному виду
  ещё с сентября, а в заголовке `Location` — нет, там голый `urljoin`.
- **Воспроизвести:** Chromium против питона.

| Location (с `https://a.com/x`) | Chromium (`new URL`) | `urljoin` |
|---|---|---|
| `/\evil.top/x` | `https://evil.top/x` | `https://a.com/\evil.top/x` |
| `\\evil.top/x` | `https://evil.top/x` | `https://a.com/\\evil.top/x` |
| `///evil.top/x` | `https://evil.top/x` | `https://a.com/evil.top/x` |

  (проверил сам: `node` + Playwright и `python3 -c "from urllib.parse import urljoin; ..."`).
  Агент прогнал сквозь `/scan`: при `Location: /\host2/x` сканер остаётся на
  исходном хосте, ни одного признака переадресации; при
  `Location: http://host1\@google.com/` — `scanned_url: google.com`, 15 SAFE,
  хотя браузер остаётся на первом хосте.
- **Где:** `backend/url_resolver.py:138`, `backend/pipeline/page_analyzer.py:273`.
- **Чем опасно:** `/\evil.top` — классический обход фильтра «только
  относительные пути» в открытых редиректах честных сайтов. Ссылка
  `доверенный.сайт/redirect?to=/\evil.top` получает вердикт доверенного
  домена, а человек уходит на `evil.top`. С настоящим доверенным доменом
  не прогоняли — подтверждена механика.
- **SSRF не открывает:** проверка адреса и подключение используют один разбор.
- **Направление:** прогонять `Location` через ту же нормализацию, что и
  входной адрес (`normalize_authority` / `normalize_scheme_separator`).

### S-04. Медленный сайт держит место в очереди 30 секунд (класс G-01)

- **Что не так:** `PAGE_TIMEOUT` и `RESOLVE_HOP_TIMEOUT` — таймауты httpx
  **на одно чтение**, а не на весь ответ; `RESOLVE_TOTAL_TIMEOUT`
  проверяется только между переходами. Сайт, отдающий байт раз в 2 секунды,
  не упирается ни в один.
- **Проверил:** по коду (так httpx понимает `timeout` — на каждое чтение);
  прогон агента (~2,5 минуты): `analyze_page` и `resolve_final_url` не вернулись
  за 45 с, `/scan` — 504 за 30 с. 20 таких сканов заняли весь
  `_scan_semaphore(20)`; честная проверка во время атаки — **28 с** вместо 0.006.
- **Где:** `backend/pipeline/page_analyzer.py:255-309`, `backend/url_resolver.py:53-62, :105`.
- **Направление:** общий `asyncio.wait_for` на весь уровень (как и для G-01).

### S-05. Тело запроса не ограничено по размеру

- **Что не так:** длина адреса (2048) проверяется после того, как всё тело
  прочитано и разобрано.
- **Воспроизвести:** TestClient, `POST /scan` с телом 100 МБ.
- **Получили (проверил сам):** 422, но пик памяти процесса **54 → 455 МБ**
  (часть — сам тестовый клиент, держащий то же тело). Агент через uvicorn:
  200 МБ → пик 700 МБ, после ответа память не вернулась.
- **Где:** проверки `Content-Length` нет ни в `backend/main.py`, ни в `Procfile`.
- **Не проверено:** режет ли прокси Render большие тела раньше приложения.
- **Направление:** отказ 413 по `Content-Length` до чтения тела.

### S-06. Ответ сообщает, во что резолвится внутреннее имя

- **Воспроизвести:** TestClient, `POST /scan {"url":"http://localhost/"}`.
- **Получили (проверил сам):** в ответе текст
  `Host 'localhost' resolves to non-public address 127.0.0.1` — и в
  `redirects.error`, и в `details.page.error`. Сервис работает как резолвер
  внутренних имён хостинга.
- **Где:** `backend/net_guard.py:131`, наружу через `url_resolver.py:121`,
  `page_analyzer.py:251`, `tls_check.py:132`.
- **Попутно:** `http://localhost/` получает **20 SAFE, достоверность 0.2**.
  Страница при достоверности < 0.5 покажет «НЕ ПРОВЕРЕНО», но клиент API
  видит `verdict: SAFE` — тот же вопрос, что в H-03.

### S-07 … S-09 — не перепроверял, со слов агента

- **S-07.** `rate_limit.py:70` читает только первую строку `X-Forwarded-For`.
  Если прокси Render **добавляет вторую строку**, а не дописывает в
  существующую, лимит обходится подставной первой строкой (локально:
  40 запросов — 40 × 200). Зависит от Render, на бою не проверено.
- **S-08.** `</url_to_analyze>` в адресе не экранируется
  (`ai_analyzer.py:169-182`). Зажим поправки держит (−999 → −15, уже покрыт
  `test_delta_is_clamped`), но −15 переводит адрес с баллом 60–74 из
  красного в жёлтый, а `summary` модели («Официальный сайт Сбербанка,
  проверен PhishGuard») показывается от имени сервиса. На живой модели не
  проверено — ключа нет, и уровень на бою выключен.
- **S-09.** DNS rebinding: `assert_url_is_safe` резолвит сам, потом httpx
  резолвит заново. С подменённым `getaddrinfo` (публичный, затем 127.0.0.1)
  уровень страницы сходил на внутренний адрес и вернул его `<title>`.
  Это известный риск из `ARCHITECTURE.md` раздел 1.1, не новая находка.
  `tls_check.py:126-138` устроен так же, но с произвольным портом — не проверено.

### Что агент проверил и не нашёл проблем

- **SSRF по форме адреса** — 41 вариант (десятичный, шестнадцатеричный,
  восьмеричный IP, `127.1`, `0`, IPv4-mapped/compatible, NAT64, 6to4,
  zone-id, юникодные цифры, метаданные облаков, CGNAT) — всё заблокировано.
  Мелочь: `fec0::1` (устаревший site-local IPv6) считается публичным.
- **SSRF через переадресации:** проверка на каждом переходе в обоих уровнях,
  чужие схемы отсекаются.
- **RDAP и CT:** домен в запрос попадает безопасно.
- **Лимит запросов:** случайный левый XFF, `/scan/stream`, `/%73can`,
  `/scan/` — держит; `/SCAN`, `//scan`, `/x/../scan` — 404. Память лимитера
  ограничена 10 000 ключей.
- **XSS:** HTML с `onerror`, `<script>` и `javascript:` во всех полях ответа
  и в адресе, ширины 390 и 1280 — ничего не исполнилось. Опасных приёмников
  в `index.html` и `api.html` нет.
- **gzip-бомба** — пик ~+130 МБ на запрос, не складывается при 10 параллельных.
- **Тяжёлый HTML** — 22 вредных входа по 256 КБ, разбор не дольше 0.5 с.
- **Утечки:** `/docs`, `/openapi.json`, `/stats` открыты (в `/stats` только
  счётчики); текст исключений в 500 наружу не уходит. В лог пишется полный
  проверяемый адрес с параметрами (`main.py:389`, `:472`) — токены из ссылок
  оседают в логах Render.
